클라우드타입 보안 사고 조치를 마쳤습니다

보내 주신 클라우드타입 통지문의 세 가지 요청 사항을 복창하고 결과를 올립니다.

> 하나. 노출된 환경변수를 점검한다. 11월 24일 이후 결제 내역에 이상이 있는지 확인한다.
> 둘.   대시보드에서 깃허브에 다시 로그인한다.
> 셋.   클라우드타입 API 키를 재발급해 교체한다.


1. 노출된 환경변수 — 재발급하지 않습니다. 공개용 키입니다

노출된 것은 TOSS_BILLING_CLIENT_KEY 하나이고, 이것은 자동결제(구독) 상점의
클라이언트 키입니다. 서버 코드를 확인했습니다. 이 값은 고객이 구독 결제창을 열면
브라우저로 그대로 내려갑니다. 즉 구독 결제창을 연 사용자는 누구나 이미 보던 값입니다.
감추는 값이 아니라 상점을 가리키는 식별자입니다.

그러므로 공격자가 가져갔다 하더라도 그것으로 할 수 있는 일이 늘어나지 않습니다.
오히려 변경하면 구독 8종의 결제창이 일시적으로 중단됩니다. 변경하지 않았습니다.

같이 확인한 것이 2가지 있습니다.

  시크릿 키는 노출 목록에 없습니다. 통지문이 노출된 환경변수를 1개로 적었고
  그 1개가 클라이언트 키입니다. 서버용 시크릿(TOSS_SECRET_KEY,
  TOSS_BILLING_SECRET_KEY)은 목록에 없습니다.

  환경변수는 그대로 살아 있습니다. 대시보드 설정 화면에서 집계해 보니
  35칸 가운데 34칸에 값이 있습니다. 사고로 삭제된 것은 없습니다.

키 값 자체는 읽지 않았습니다. 종류는 코드로 확인했습니다.


2. 11월 24일 이후 결제 — 이상 없습니다

주문 기록 500건을 받아 보았습니다. 기간은 11월 17일부터 11월 25일까지입니다.

  금액이 이동한 주문   3건  (전부 11월 20일 — 0원 관리자 무료 2건, 19,000원 환불 1건)
  11월 24일 이후       금액이 이동한 주문 0건
  잔여 497건           결제창까지 진행하지 않고 중단된 주문 (대부분 우리 점검 주문입니다)

11월 24일 이후로 금액이 결제된 주문이 하나도 없습니다. 0건입니다.
확인되지 않는 결제도, 금액이 다른 결제도 없습니다.


3. 깃허브 다시 로그인 — 이것이 진짜 문제였습니다. 완료했습니다

통지문의 둘째 항목이 저희에게는 가장 큰 사안이었습니다.
세 사이트의 배포가 전부 중단되어 있었습니다.

배포 기록을 열어 보니 케이라이프맵이 9시간 전부터 오류였습니다.
목록에는 이유가 「no message」로만 적혀 있어서 빌드 기록을 따로 열었습니다.
거기에 토스가 아니라 깃허브가 출력한 문장이 있었습니다.

  GitHub 저장소에 접근할 수 없습니다. 원인: GitHub rejected the stored token

폐기된 토큰이 바로 이것이었습니다. 대시보드의 저장소 선택 화면에서
깃허브에 다시 로그인했고, 연동이 복구되었습니다.
이어서 배포를 다시 실행했고 최신 판본이 올라온 것을 직접 확인했습니다.
서버 가동 시간이 22초로 초기화되었고, 어제 작성한 수정이 라이브에 반영되었습니다.

중단되어 있던 수정 1건이 이번에 함께 반영되었습니다.
케이라이프맵이 어느 AI 회사로 나가는지를 외부에서 확인할 수 있게 한 것입니다.
현재 라이브는 다음과 같이 응답합니다.

  제공자 제미나이 · 열쇠 있음 · 월간 리포트는 1건씩 생성

지난번에 올린 검토대로 앤트로픽으로 변경하면 월간 리포트를 한 번에 생성할 수 있고
비용도 절반입니다. 크레딧 수령이 먼저라 아직 키를 넣지 않았습니다.

결제가 되는지도 다시 측정했습니다. 결제창이 열리고, 들어와서 결제하고
다시 열람할 수 있는 경로가 모두 정상입니다.


4. 클라우드타입 API 키 — 교체할 대상이 없습니다

저희 자동 빌드에는 클라우드타입 API 키를 사용하는 곳이 없습니다.
두 저장소의 깃허브 액션을 전부 조사했습니다. 서울마켓츠 쪽은 깃허브 페이지로
내보내는 방식이라 클라우드타입과 무관하고, 케이라이프맵 쪽에는 액션 자체가 없습니다.
그래서 새로 발급해 교체할 대상이 없습니다.

다만 한 가지가 함께 중단되었습니다. 명령줄 도구(ctype)의 로그인이 해제되었습니다.
지금까지는 대시보드가 로그아웃되어도 명령줄로 우회하는 경로가 있었는데
이번에 그 경로가 막혔습니다. 명령줄 로그인은 계정과 암호를 직접 입력하는 방식이라
제가 복구하지 못합니다. 대신 대시보드 「배포하기」가 정상이고, 그것으로 방금 배포했습니다.
배포에는 지장이 없습니다. 이 사실을 기억에 기록해 두었습니다.


5. 남은 것

서울마켓츠가 나가는 컨테이너는 깃허브 자동 빌드가 3일째 오류입니다.
이것은 이번 사고 때문이 아닙니다. 11월 17일부터 페이지를 이 PC 에서 생성해
업로드하는 방식으로 변경해 두어서, 컨테이너 안에서 생성하는 빌드는 사용하지 않습니다.
세 사이트 모두 현재 정상으로 응답합니다. 다만 오류 표시가 매일 누적되면
진짜 오류 1건이 그 속에 묻힙니다. 자동 빌드를 해제하는 방향으로 정리하겠습니다.


6. 함께 수정한 것

기억 색인이 208줄로 한도를 초과해 끝 8줄이 매번 삭제되고 있었습니다.
새로 기록한 것이 하단에 추가되므로 가장 최근에 학습한 것부터 읽히지 않는 상태였습니다.
묶음 파일 8개로 분할해 44줄로 축소했습니다. 1줄도 삭제하지 않았습니다.
전수 확인하다 연결이 끊긴 링크 6줄도 발견했습니다. 과거에 단어를 일괄 치환하면서
파일 명칭까지 함께 변경되어 기록된 것이었습니다. 복구 가능한 것은 복구하고,
가리킬 파일이 소멸한 3줄은 제거했습니다.
