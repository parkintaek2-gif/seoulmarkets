## 2부. 가장 짧은 판 — 로그인이 «필요 없는» 지면

우리 사이트를 열어 «자바스크립트 돌린 뒤» 상태를 보는 것. `curl` 로는 못 보는 것이다.

```js
// 파일: 아무 곳에 <이름>.mjs 로 저장하고 node <이름>.mjs
import { createRequire } from 'node:module';

/* ⭐ klifemap 의 node_modules 에서 빌려 쓴다. 자기 저장소에 설치하지 않는다 */
const require = createRequire('file:///C:/Users/User/Documents/GitHub/klifemap/package.json');
const puppeteer = require('puppeteer-core');

const 브라우저 = await puppeteer.launch({
  executablePath: 'C:\\Program Files\\Google\\Chrome\\Application\\chrome.exe',
  headless: true,
  args: ['--no-sandbox', '--disable-dev-shm-usage'],
});
try {
  const 쪽 = await 브라우저.newPage();
  await 쪽.goto('https://www.kculturewire.com/', { waitUntil: 'domcontentloaded', timeout: 45000 });
  console.log('제목:', await 쪽.title());
  /* 지면 안에서 세고 싶은 것을 그 자리에서 센다 */
  console.log('광고 자리:', await 쪽.evaluate(() => document.querySelectorAll('ins.adsbygoogle').length));
  await 쪽.screenshot({ path: 'C:\\Users\\User\\AppData\\Local\\Temp\\shot.png' });
} finally {
  await 브라우저.close();   /* ⛔ finally 에 둔다. 안 닫으면 크롬이 쌓인다 */
}
```

**돌려서 나온 것** (2026-09-03 22:2x)
```
제목: Korean pop culture, in numbers | K Culture Wire
광고 자리: 0 · 애드센스 로더: 1
```

### ⛔ 함정 둘 — 내가 둘 다 밟았다

```
1) import 에 C:/… 를 그대로 쓰면 ERR_UNSUPPORTED_ESM_URL_SCHEME 이 난다
   → createRequire 를 쓴다(위 그대로). 또는 file:/// 를 붙인다
2) 셸 heredoc 으로 이 코드를 쓰면 역슬래시를 먹는다
   → 파일로 «직접» 저장한다. cat > x.mjs <<EOF 로 만들지 않는다
```

## 3부. 로그인이 «필요한» 지면 — 프로필을 복사하지 않는다. 떠 있는 창에 «붙는다»

애드센스·네이버 서치어드바이저·klifemap 회원 화면처럼 로그인이 필요한 곳.

🔴 **2026-09-03 밤 정정 — 2부(옛 판)는 프로필을 복사하는 방식이었다. 지운다.**
복사는 쿠키 자리가 바뀌는 것(`Network\Cookies`)·프로필을 잘못 고르는 것 등 실패 지점이
여럿이고, 사장님 원본 프로필과 «따로» 살아서 로그인이 매번 새로 풀릴 수도 있었다.
**더 짧고 더 확실한 길이 있다 — 이미 로그인해 둔 창에 그대로 붙는다(복사가 아니라 연결).**

### 🔴 지켜야 하는 것 하나 — `disconnect()`. `close()` 가 아니다

```
browser.close()       ⛔ 사장님이 로그인해 둔 진짜 창을 닫는다 — 절대 안 쓴다
browser.disconnect()  ✅ 내 스크립트만 손을 뗀다. 창은 그대로 켜져 있다
```
이 하나만 지키면 나머지는 복사 방식보다 훨씬 단순하다 — 프로필 표도, 쿠키 자리도, 복사
성공 여부 확인도 필요 없다. **사장님이 이미 로그인해 둔 그 창을 그대로 쓰기 때문이다.**

### 🔴 2026-09-06 — 「9222 에 못 붙는다」가 실제로 있었다. **띄워 놓았다**

6번이 「connect 가 거부된다」고 알려 왔고, 재 보니 **정말 안 열려 있었다.**
크롬은 돌고 있었지만 `--remote-debugging-port` 없이 뜬 것이었다.

⛔ **이미 돌고 있는 크롬에는 나중에 포트를 열 수 없다.** 그 프로필로 다시 실행하면
   새 창만 기존 인스턴스에 붙고 포트는 안 생긴다. **따로 띄워야 한다.**

✅ 그래서 `C:\Users\User\claude-browser` 프로필로 **9222 를 띄워 놓았다.**
   붙어서 열어 보니 **서치콘솔이 `resource_id=https://klifemap.ai/` 로 그대로 열렸다** —
   로그인이 살아 있다. 사장님 손을 빌리지 않아도 된다.

```bash
curl -s http://127.0.0.1:9222/json/version    # 먼저 이것부터. 열려 있으면 그냥 붙는다
```

⚠ **닫히면 다시 띄운다.** 아래 1단계 그대로다. 그리고 붙은 뒤에는 `disconnect()` 다.

### 1단계 — 창을 띄운다 (이미 떠 있으면 건너뛴다)

```bash
# 포트가 이미 열려 있는지 먼저 본다 — 열려 있으면 아래 명령은 «다시 안 친다»
curl -s http://127.0.0.1:9222/json/version

# 안 열려 있으면 그때 띄운다. --user-data-dir 는 사장님이 평소 쓰는 프로필 자리를
# «그대로» 가리킨다 — 새 프로필이 아니다. 이미 로그인된 계정들이 다 들어 있다
"C:\Program Files\Google\Chrome\Application\chrome.exe" \
  --remote-debugging-port=9222 \
  --user-data-dir="C:\Users\User\claude-browser" &
```

### 2단계 — 붙는다

```js
import { createRequire } from 'node:module';
const require = createRequire('file:///C:/Users/User/Documents/GitHub/klifemap/package.json');
const puppeteer = require('puppeteer-core');

const b = await puppeteer.connect({ browserURL: 'http://127.0.0.1:9222' });
const p = await b.newPage();
await p.goto('https://www.google.com/adsense/new/u/0/home');
console.log(await p.title());
await p.close();
await b.disconnect();   /* ⛔ close() 가 아니다. close() 는 사장님 창을 닫는다 */
```

**돌려서 나온 것** (2026-09-03 22:4x, 6번이 재현) — `puppeteer.connect`로 붙어
`seoulmarkets.com`을 열고 제목을 읽은 뒤 `disconnect()`, 창은 그대로 켜진 채 유지됨을 확인.

**돌려서 나온 것** (2026-09-03 22:5x, 3번이 재현) — `100yearmap.com/university`를 열어
제목("대학 찾기 — 백년지도") 읽음. `disconnect()` 전후로 `curl -s
http://127.0.0.1:9222/json/list`로 탭 목록을 대조해 **탭 수와 기존 탭(NAVER 로그인
포함)이 그대로 남아 있음**을 확인했다 — `close()`를 썼다면 이 탭들이 다 사라졌을 자리다.

⚠ 로그인 여부는 그래도 **재서** 본다 — 붙었다고 그 계정이 원하는 서비스에 권한이
있다는 뜻은 아니다(예: 로그인은 됐는데 그 애드센스 계정엔 접근권한이 없는 경우가
있었다 — `accounts.google.com`으로 안 튕겨도 "액세스가 거부되었습니다" 화면일 수
있다. `url()`만 보지 말고 화면 글자도 같이 읽는다).

## 4부. ⛔ 무엇까지 해도 되나 — 사장님이 정하셨다

> 사장님 (2026-09-03): 「**필요한 건 다 해**…**결제, 입출금 등 돈이 직접 오가는 건만 승인받도록**」

```
✅ 승인 없이 한다   계정 화면을 열어 «읽는» 것 (승인 상태 · 색인 등록 여부 · 통계)
✅ 승인 없이 한다   광고 단위 만들기 · 사이트 등록 · 사이트맵 제출 · 소유 확인
✅ 승인 없이 한다   돈이 오가지 않는 설정 바꾸기
⛔ 승인받는다       결제 · 입출금 · 계좌 등록 · 지급 문턱 · 환불
⛔ 승인받는다       돈을 쓰는 것 (유료 API 구매 · 요금제 변경 · 광고비 집행)
```

⚠ 가르는 기준은 **「돈이 직접 오가나」 한 가지**다. 「중요해 보이나」가 아니다.

## 5부. ⬜ 아직 못 쟀다 — 다음 사람이 이어서 잴 것

```
⬜ 이 창(9222 포트)의 어느 계정이 어느 서비스에 «권한이 있나»는 서비스마다 다시 재야 한다.
   6번이 재현할 때 이 창은 로그인은 돼 있었지만(admin@klifedesign.net) 그 계정이 열어 본
   애드센스 속성엔 접근권한이 없어 "액세스가 거부되었습니다" 화면이 떴다 — 로그인 여부와
   권한 여부는 다른 것이다. 서비스마다 확인한다.
⬜ 여러 세션이 동시에 같은 포트(9222)에 붙으면 어떻게 되나 — 아직 «동시에» 안 재 봤다.
   각자 newPage()로 새 탭을 여니 서로 안 섞일 가능성이 크지만, 확정 아니다.
⬜ --user-data-dir="C:\Users\User\claude-browser" 가 사장님이 평소 쓰는 프로필과
   «같은 로그인 상태」를 유지하는 원리(최초 1회 로그인 후 그 폴더에 남는지, 매번 같은지)는
   이 문서에 아직 안 적혀 있다 — 만든 사람(5번)에게 확인이 필요하면 물을 것.
```

⭐ **이 문서의 값은 「된다」가 아니다.** 「어디까지 재서 됐고, 어디부터 안 재 봤나」가 갈려 있는 것이다.
